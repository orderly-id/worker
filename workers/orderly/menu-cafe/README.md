# Menu Cafe

Worker resmi Orderly untuk mengelola kategori dan item menu cafe. Setiap pemilik hanya memiliki satu instance `@menu-cafe.<username>`. Data disimpan per instance dan dapat dikelola oleh owner/editor melalui workspace atau chat; guest hanya dapat melihat.

Package ini menjadi sumber manifest, prompt AI, action planner, schema workspace, aset, dan pengujian Worker. Penyimpanan serta otorisasi tetap dijalankan oleh capability host Orderly Core.

Route kanonis `/@menu-cafe.<username>/catalog` menampilkan kategori berbasis galeri gambar. Saat kategori dibuka, item ditampilkan dalam galeri dan dapat dibuat atau diedit melalui form foto, nama, harga, deskripsi, serta status ketersediaan. Urutan item dapat diubah dengan drag-and-drop atau aksi pindah ke atas/bawah dan disimpan sebagai `position`. File foto disimpan oleh media storage Core dalam lingkup instance dan item; model Worker hanya menyimpan `image_url`.

Dashboard instance menyediakan akses terpisah ke katalog dan pesanan. Route `/@menu-cafe.<username>/order` menampilkan pesanan aktif, sedangkan ikon riwayat membuka `/@menu-cafe.<username>/order/history`. Pesanan disimpan sebagai data terstruktur yang ditautkan ke pesan struk, percakapan, pelanggan, dan snapshot item. Pesanan baru menunggu konfirmasi selama 15 menit lalu otomatis dibatalkan jika tidak ditanggapi. Pengelola dapat menerima atau membatalkan pesanan yang menunggu; pesanan yang diterima menjadi **Diproses** dan dapat diselesaikan atau dibatalkan.

Aksi status tersedia di kartu pesanan workspace dan di bawah struk pada chat pihak cafe. Setiap tindakan operator otomatis menandai percakapan terkait sebagai dibaca dan disiarkan secara realtime. Kartu pesanan menyediakan pintasan chat pelanggan, sementara status **Diproses** menampilkan durasi berjalan sejak pesanan diterima.

Dashboard `/@menu-cafe.<username>` menampilkan ringkasan seluruh data instance: total pesanan, pesanan sukses, pesanan dibatalkan, total pendapatan, dan **Pelanggan Unik** berdasarkan jumlah akun customer berbeda yang pernah membuat pesanan. Pendapatan hanya dijumlahkan dari pesanan berstatus **Selesai**. Dashboard juga menampilkan grafik tren jumlah pesanan harian selama tujuh hari terakhir. Setiap kategori yang sudah memiliki pesanan mendapatkan satu pie card tersendiri dengan judul **Top 10 `<Nama Kategori>` Dipesan**, berdasarkan total kuantitas dari pesanan yang tidak dibatalkan. Kategori tanpa pesanan tidak menampilkan card; satu menu yang baru sekali dipesan langsung menghasilkan satu slice dan analitik diperbarui melalui event realtime pesanan. Snapshot pesanan baru menyimpan identitas kategori agar analitik historis tetap benar setelah menu diedit atau dipindahkan; data lama menggunakan kategori menu saat ini sebagai fallback. Route turunan `/catalog`, `/order`, dan `/order/history` tetap menjadi area Workspace operasional.

Setting `menu_enabled` bersifat nonaktif secara default. Ketika owner atau editor mengaktifkan **Aktifkan Menu**, user lain yang membuka chat reguler dengan owner melihat tombol Menu dan panel katalog berbasis kategori. Tombol ini tidak muncul pada chat langsung dengan Worker. Produk tersedia maupun tidak tersedia tetap ditampilkan, tetapi produk yang tidak tersedia tidak dapat ditambahkan. Kontrol jumlah membentuk preview receipt read-only dan total nominal pada bar composer; tombol Kirim merender receipt menjadi PNG lalu mengirimnya melalui pipeline pesan gambar reguler.
