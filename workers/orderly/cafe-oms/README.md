# Cafe Order Management System

Worker resmi Orderly untuk mengelola katalog, pesanan, pelanggan, dan operasional cafe. Setiap pemilik hanya memiliki satu instance `@cafe-oms.<username>`. Data disimpan per instance dan dapat dikelola oleh owner/editor melalui workspace atau chat; guest hanya dapat melihat.

Package ini menjadi sumber manifest, prompt AI, action planner, schema workspace, aset, dan pengujian Worker. Penyimpanan serta otorisasi tetap dijalankan oleh capability host Orderly Core.

Route kanonis `/@cafe-oms.<username>/catalog` menampilkan kategori berbasis galeri gambar. Saat kategori dibuka, item ditampilkan dalam galeri dan dapat dibuat atau diedit melalui form foto, nama, harga, deskripsi, serta status ketersediaan. Urutan item dapat diubah dengan drag-and-drop atau aksi pindah ke atas/bawah dan disimpan sebagai `position`. File foto disimpan oleh media storage Core dalam lingkup instance dan item; model Worker hanya menyimpan `image_url`.

Dashboard instance menyediakan akses terpisah ke katalog dan pesanan. Route `/@cafe-oms.<username>/order` menampilkan pesanan aktif, sedangkan ikon riwayat membuka `/@cafe-oms.<username>/order/history`. Pesanan disimpan sebagai data terstruktur yang ditautkan ke pesan struk, percakapan, pelanggan, dan snapshot item. Pesanan baru menunggu konfirmasi selama 15 menit lalu otomatis dibatalkan jika tidak ditanggapi. Pengelola dapat menerima atau membatalkan pesanan yang menunggu; pesanan yang diterima menjadi **Diproses** dan dapat diselesaikan atau dibatalkan.

Aksi status tersedia di kartu pesanan workspace dan di bawah struk pada chat pihak cafe. Setiap tindakan operator otomatis menandai percakapan terkait sebagai dibaca dan disiarkan secara realtime. Kartu pesanan menyediakan pintasan chat pelanggan, sementara status **Diproses** menampilkan durasi berjalan sejak pesanan diterima.

Dashboard `/@cafe-oms.<username>` menampilkan ringkasan seluruh data instance: total pesanan, pesanan sukses, pesanan dibatalkan, total pendapatan, dan **Pelanggan Unik** berdasarkan jumlah akun customer berbeda yang pernah membuat pesanan. Pendapatan hanya dijumlahkan dari pesanan berstatus **Selesai**. Dashboard juga menampilkan grafik tren jumlah pesanan harian selama tujuh hari terakhir. Setiap kategori yang sudah memiliki pesanan mendapatkan satu pie card tersendiri dengan judul **Top 10 `<Nama Kategori>` Dipesan**, berdasarkan total kuantitas dari pesanan yang tidak dibatalkan. Kategori tanpa pesanan tidak menampilkan card; satu menu yang baru sekali dipesan langsung menghasilkan satu slice dan analitik diperbarui melalui event realtime pesanan. Snapshot pesanan baru menyimpan identitas kategori agar analitik historis tetap benar setelah menu diedit atau dipindahkan; data lama menggunakan kategori menu saat ini sebagai fallback. Route turunan `/catalog`, `/order`, dan `/order/history` tetap menjadi area Workspace operasional.

Setting `menu_enabled` bersifat nonaktif secara default. Ketika owner atau editor mengaktifkan **Aktifkan Menu**, user lain yang membuka chat reguler dengan owner melihat tombol Menu dan panel katalog berbasis kategori. Tombol ini tidak muncul pada chat langsung dengan Worker. Produk tersedia maupun tidak tersedia tetap ditampilkan, tetapi produk yang tidak tersedia tidak dapat ditambahkan. Saat katalog terbuka, tombol Menu berubah menjadi Cancel dan tombol Kirim disembunyikan; Cancel menutup panel sekaligus mengosongkan pilihan. Setelah tombol total membuka receipt read-only, kontrol kembali menjadi Menu agar user dapat kembali ke katalog tanpa kehilangan pilihan, sedangkan tombol **Selesai** menjadi hijau. Selesai merender receipt menjadi PNG ke preview composer; tombol Kirim baru muncul aktif setelah preview terbentuk dan kemudian mengirimnya melalui pipeline pesan gambar reguler.

Panel receipt menyediakan input `@username` untuk mengundang teman memesan bersama. Undangan disimpan sebagai metadata pesan reguler, dikirim realtime ke percakapan tujuan, dan ditampilkan sebagai kartu dengan nomor pesanan serta tombol Menu. Tombol tersebut melakukan join ke sesi pesanan, membuka percakapan dengan pemilik cafe, dan memuat katalog yang benar. Pilihan menu disimpan dalam sesi server-authoritative yang memiliki daftar anggota dan nomor versi monotonik. Setiap perubahan kuantitas dikirim sebagai delta, dikunci secara transaksional, lalu disiarkan ke seluruh anggota; client mengabaikan event versi lama. Chip waktu menandai undangan pending dan berubah menjadi status joined ketika penerima membuka Menu. Checkout membaca kuantitas dari sesi server dan menutup sesi setelah pesanan berhasil dibuat, sehingga semua anggota selalu melihat keranjang dan nomor pesanan yang sama.

Saat katalog atau receipt diperluas, **Order Session Bar** tampil di atas navbar dengan indikator hijau serta kontrol minimize, maximize, dan close. Panel operasional menggunakan seluruh tinggi tersisa hingga navbar tanpa batas tinggi card. Minimize mempertahankan sesi dan mengembalikan interface chat, tetapi mengganti composer reguler dengan kartu sesi ringkas; maximize membuka kembali panel terakhir, sedangkan close membatalkan sesi bagi creator atau mengeluarkan participant dari sesi.
