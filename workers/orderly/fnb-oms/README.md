# FnB Order Management System

Worker resmi Orderly untuk mengelola katalog, pesanan, pelanggan, dan operasional bisnis makanan dan minuman. Setiap pemilik hanya memiliki satu instance `@fnb-oms.<username>`. Data disimpan per instance dan dapat dikelola oleh owner/editor melalui workspace atau chat; guest hanya dapat melihat.

Package ini menjadi sumber manifest, prompt AI, action planner, schema workspace, aset, dan pengujian Worker. Penyimpanan serta otorisasi tetap dijalankan oleh capability host Orderly Core.

Route kanonis `/@fnb-oms.<username>/catalog` menampilkan kategori berbasis galeri gambar. Saat kategori dibuka, item ditampilkan dalam galeri dan dapat dibuat atau diedit melalui form foto, nama, harga, deskripsi, serta status ketersediaan. Urutan item dapat diubah dengan drag-and-drop atau aksi pindah ke atas/bawah dan disimpan sebagai `position`. File foto disimpan oleh media storage Core dalam lingkup instance dan item; model Worker hanya menyimpan `image_url`.

Dashboard instance menyediakan tombol **Worker** menuju `/@fnb-oms.<username>/workspace`. Workspace utama menampilkan menu **Order**, **Catalog**, **Respond**, dan **Setting**. Route `/@fnb-oms.<username>/catalog` mengelola katalog, `/order` menampilkan pesanan aktif, `/order/history` menampilkan riwayat, `/setting` memusatkan General Setting, User Access, Instance Connect, Worker Information, dan Permissions dalam satu card tetap, sedangkan `/respond` mengelola respons cepat. Icon `Command` pada navbar Respond membuka `/respond/action`. Halaman **Action Button** menampilkan seluruh tombol workflow bawaan beserta toggle tersimpan untuk menampilkan atau menyembunyikannya dari card Respond; fungsi tambah dan editor action tidak tersedia. Pesanan disimpan sebagai data terstruktur yang ditautkan ke pesan struk, percakapan, pelanggan, dan snapshot item. Pesanan terkirim masuk ke state `new` dengan pesan **Menunggu konfirmasi** dan countdown server selama 15 menit. Pada state ini hanya **Cancel Pesanan** dan **Terima Pesanan** yang aktif. Timeout otomatis memindahkan order ke state `cancel` dengan pesan **Pesanan dibatalkan**.

Aksi status tersedia di kartu pesanan workspace dan tab **Action** pada Response composer. Kartu pesanan di chat hanya menampilkan informasi serta **Detail Order**, tanpa tombol aksi status. Konfigurasi `response_actions` memakai empat jenis capability tombol: `accept.button`, `cancel.button`, `flow.button`, dan `end.button`. **Terima Pesanan** memindahkan order ke state `process`, mengatur pesan **Pesanan diproses**, dan memulai timer maju maksimal 180 menit. Selama `process`, semua tombol aktif kecuali `accept.button`; **Pesanan Siap**, **Antar Pesanan**, dan **Pesanan Sampai** adalah `flow.button` yang hanya mengganti pesan menjadi **Pesanan sudah siap**, **Pesanan sedang di antar**, atau **Pesanan sudah sampai** tanpa mengubah state dan tanpa mereset timer. Hanya `flow.button` terakhir yang dibuat pasif dan ditolak jika langsung diulang. Ketika operator memilih flow lain, flow sebelumnya aktif kembali dan flow terbaru menjadi pasif; state ini disimpan pada order agar konsisten setelah refresh serta pembaruan realtime. Warna pesan proses berubah per jam: hijau pada jam pertama, kuning pada jam kedua, dan merah pada jam ketiga. Timeout 180 menit otomatis membatalkan pesanan. `end.button` memindahkan order ke state `end`, menampilkan **Pesanan selesai** berwarna hijau, menghentikan timer, dan menonaktifkan semua action. Setiap tindakan operator otomatis menandai percakapan terkait sebagai dibaca dan disiarkan secara realtime.

Dashboard `/@fnb-oms.<username>` menampilkan ringkasan seluruh data instance: total pesanan, pesanan sukses, pesanan dibatalkan, total pendapatan, dan **Pelanggan Unik** berdasarkan jumlah akun customer berbeda yang pernah membuat pesanan. Pendapatan hanya dijumlahkan dari pesanan berstatus **Selesai**. Dashboard juga menampilkan grafik tren jumlah pesanan harian selama tujuh hari terakhir. Setiap kategori yang sudah memiliki pesanan mendapatkan satu pie card tersendiri dengan judul **Top 10 `<Nama Kategori>` Dipesan**, berdasarkan total kuantitas dari pesanan yang tidak dibatalkan. Kategori tanpa pesanan tidak menampilkan card; satu menu yang baru sekali dipesan langsung menghasilkan satu slice dan analitik diperbarui melalui event realtime pesanan. Snapshot pesanan baru menyimpan identitas kategori agar analitik historis tetap benar setelah menu diedit atau dipindahkan; data lama menggunakan kategori menu saat ini sebagai fallback. Route turunan `/catalog`, `/order`, dan `/order/history` tetap menjadi area Workspace operasional.

Setting `menu_enabled` bersifat nonaktif secara default. Ketika owner atau editor mengaktifkan **Aktifkan Menu**, user lain yang membuka chat reguler dengan owner melihat tombol Menu dan panel katalog berbasis kategori. Tombol ini tidak muncul pada chat langsung dengan Worker. Produk tersedia maupun tidak tersedia tetap ditampilkan, tetapi produk yang tidak tersedia tidak dapat ditambahkan. Sesi membuat nomor order sejak katalog dibuka. Setiap anggota mengelola **My Order**, menekan **Selesai Memilih** untuk mengunci pilihannya, dan melihat akumulasi seluruh anggota melalui **Total**. Hanya host yang dapat melanjutkan total siap ke preview composer dan mengirim pesanan. Preview menyediakan catatan, detail terstruktur, aksi kembali ke katalog, hapus draft, dan kirim tanpa kontrol lampiran atau mikrofon. Setelah dikirim, preview dan panel pesanan ditutup sehingga user kembali ke chat; dokumen struk tidak dibuka otomatis dan tetap dapat dikunjungi melalui **Detail Order**.

Setting `profile_menu_enabled` (**Display Menu**) terpisah dari `menu_enabled`. Jika aktif, profil publik owner menampilkan navbar **Links / Menu** di atas kontainer link dan tab Menu berisi katalog per kategori. Pengaturan ini tidak otomatis mengaktifkan Menu Button pada chat. Keduanya nonaktif secara default dan dapat digunakan secara independen.

Order Session Bar menyediakan daftar anggota serta aksi invite, share, minimize, dan close. Undangan disimpan sebagai metadata pesan reguler, dikirim realtime ke percakapan tujuan, dan ditampilkan sebagai kartu dengan nomor pesanan serta tombol Join/Menu. Pilihan menu disimpan dalam sesi server-authoritative yang memiliki daftar anggota dan nomor versi monotonik. Setiap perubahan kuantitas dikirim sebagai delta, dikunci secara transaksional, lalu disiarkan ke seluruh anggota; client mengabaikan event versi lama. Checkout membaca kuantitas dari sesi server sehingga semua anggota selalu melihat keranjang dan nomor pesanan yang sama. Jika host menutup sesi kolaboratif, Core meminta konfirmasi lalu menyimpan status **Pesanan dibatalkan**; tombol kartu berubah menjadi **History Order**.

Setiap sesi yang menjadi history memiliki dokumen permanen berotorisasi pada `/oms/{order-number}_{document-key}`. `document-key` memakai 128-bit cryptographically secure random value dan bukan nomor urut yang dapat ditebak. Dokumen menyimpan snapshot nama item, harga, kuantitas, subtotal, total, serta pesanan per anggota agar histori tidak berubah ketika katalog kemudian diedit. Anggota sesi dan user yang memiliki akses sah ke instance dapat membuka file; mengetahui URL saja tidak melewati pemeriksaan akses. Draft pribadi yang dihapus atau draft kedaluwarsa yang belum pernah dikirim tidak menghasilkan history.
